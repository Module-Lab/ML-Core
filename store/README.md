# Store — витрина модулей и доверие

Здесь живут **доставка модулей и данные доверия**. Не путать с вкладкой **Releases**:
туда идёт только ядро / API-либы / официальные модули. Чужие модули, манифесты и ключи —
это содержимое `store/` (отдаётся как обычные файлы репы по `raw.githubusercontent.com`).

Доверие даёт **подпись + публичный корень, защещённый в ядре**, а не приватность этой репы.
Репа публичная — и это нормально: без приватного ключа корня подделать статус «доверен» нельзя.

## Структура
```
store/
├─ index.json                 каталог витрины (список модулей для загрузки/показа)
├─ keys/trust.json            итоговый файл доверия = то, что клиент кладёт в config/modlex-trust.json
├─ modules/<id>/<version>/    <id>-<version>.jar + <...>.jar.modlex.json (подписано автором)
│  └─ page.md                 (опционально) кастомная страница модуля от автора
├─ authors/<keyId>/           author.pub + rootSignature (сертификат автора от корня)
└─ revoked/
   ├─ keys/<keyId>.json       один файл = отозванный ключ автора
   └─ hashes/<sha256>.json    один файл = отозванная конкретная сборка
```
Папка модуля ищется по стабильному ASCII-`<id>`; человекочитаемое имя — в манифесте/`index.json`.

## Как появляется доверие
- **Автор** подписывает свой jar СВОИМ ключом (`ModuleSigner sign`). Приватник автора никуда не уходит.
- **Корень (владелец стора)** заверяет публичный ключ автора (`cert`) → запись в `authors/<keyId>/`.
  Только после этого модули автора показывают статус «✓ доверен».
- **Отзыв** — добавить файл в `revoked/…` (или убрать, чтобы вернуть).

`keys/trust.json` **собирается автоматически** из `authors/` + `revoked/` (шаг CI), руками его не
редактировать — источник истины это мелкие файлы по авторам/отзывам, а не один огромный blob.

## Формат `keys/trust.json`
```json
{
  "rootPublicKey": "<base64 X.509 публичного корня>",
  "authors": [ { "keyId": "...", "publicKey": "...", "rootSignature": "..." } ],
  "revokedKeyIds": [ "..." ],
  "revokedHashes": [ "..." ]
}
```
